# AI 文学医学健康每日情报网站设计

## 目标

搭建一个面向学生与研究者的动态视觉网站，每天自动更新 AI 新闻、文学动态、医学健康文献，并用中文摘要帮助用户快速判断哪些内容值得阅读。

第一版重点是做出可运行、可扩展、视觉完成度高的网站。它应当像一个每日情报仪表盘，而不是普通博客或营销页。

## 已确认选择

- 更新方式：自动抓取摘要。
- 受众：学生与研究者。
- 首页重点：每日精选。
- 视觉方向：深色未来科技感、数据感、适度动态效果。
- 内容范围：AI 新闻与论文、文学动态与文献、医学健康文献与权威资讯。

## 推荐实现范围

第一版包含以下页面与能力：

- 首页：展示每日精选、更新时间、三个频道入口、精选内容卡片。
- 频道筛选：AI、文学、医学健康。
- 内容卡片：标题、中文摘要、来源、发布时间、可信度/类型标签、原文链接。
- 今日重点：从当天内容里挑出最值得读的 3 到 6 条。
- 搜索与标签：按关键词、频道、内容类型筛选。
- 自动更新脚本：从可信公开来源抓取内容，生成本地数据文件供网站读取。
- 空状态与错误状态：抓取失败时显示最近一次成功更新的数据，并提示更新时间。

第一版不包含用户登录、多人后台、付费系统、评论区、复杂 CMS。这些会显著增加范围，不适合第一步。

## 内容来源策略

采用“可靠与热点平衡”的策略：

- AI：arXiv、研究机构/公司官方博客、主流技术新闻 RSS。
- 医学健康：PubMed、WHO、CDC、医学期刊或指南来源。
- 文学：开放文学新闻源、出版社/期刊动态、文学研究相关 RSS 或开放检索结果。

每条内容都必须保留原始链接。医学健康内容需要明显标注“仅供学习研究，不替代专业医疗建议”。

## 数据更新流程

系统每天运行抓取脚本：

1. 读取配置中的来源列表。
2. 抓取 RSS、公开 API 或网页公开元数据。
3. 统一整理成结构化条目。
4. 去重并按发布时间排序。
5. 为条目生成中文摘要、关键词、频道、内容类型和推荐理由。
6. 输出为网站可读取的数据文件。

如果暂时没有配置 AI 摘要 API，第一版先使用来源自带摘要和规则化摘要，保留接口位置，后续可接 OpenAI 或其他模型。

## 前端设计

首页首屏直接进入可用体验：

- 顶部：站点名、更新时间、频道切换、搜索入口。
- 主区域：今日精选大卡片和实时信息流。
- 侧栏或右侧区域：来源热度、研究主题、医学健康提醒。
- 动效：数据流背景、卡片进入动画、频道切换过渡、更新时间脉冲提示。

视觉基调：

- 深色底，但避免只有蓝紫一种颜色。
- 使用青色、绿色、白色、少量红/橙提示色建立信息层级。
- 卡片圆角控制在 8px 左右。
- 信息密度适合研究者扫描阅读，不做空泛大标题页面。

## 技术方案

推荐使用 Next.js 或 Vite + React。考虑当前是从空目录开始，第一版可使用 Vite + React，开发速度快，结构清晰。

建议结构：

- `src/App.jsx`：页面结构与主交互。
- `src/components/`：卡片、频道筛选、搜索、统计模块。
- `src/data/daily-feed.json`：网站读取的内容数据。
- `scripts/update-feed.mjs`：抓取和整理内容的脚本。
- `public/`：静态资源。

## 错误处理

- 抓取失败时不清空旧数据。
- 页面显示最近成功更新时间。
- 对缺少摘要、时间或来源的条目做降级展示。
- 医学健康频道始终显示学习研究提示。

## 验证

实现完成后需要验证：

- 网站能在本地启动并访问。
- 首页、频道筛选、搜索可用。
- 数据文件能被页面正确读取。
- 更新脚本能生成或刷新内容数据。
- 桌面与移动端布局不重叠、不溢出。
- 医学健康条目带有免责声明。
